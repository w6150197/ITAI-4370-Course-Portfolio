# Reflection 2 — Applying AI to Telecommunications Problems

This course showed me that AI in telecommunications is not just a chatbot or an automated feature. It can support traffic prediction, resource management, anomaly detection, and network planning. I practiced these ideas through Python exercises and simulations, which helped me understand what an algorithm actually needs as input and how to evaluate its output.

The Random Forest traffic lab was one of the clearest examples. I used historical and calendar features to predict network demand and examined test error and feature importance. I also learned that a good score is not enough: a feature calculated with future data can make a forecast look stronger than it would be in a real deployment. That lesson changed how I think about model validation.

The edge AI lab taught me to compare more than accuracy. A smaller model may fit a constrained device better, while quantization can affect model size and prediction quality. The midterm then brought several methods together: SimPy for packet flow, Mesa for agents and congestion, and regression for route traffic. Some simulated behaviors did not occur as expected, which reminded me to report actual observations rather than only the intended design.

My skills improved in Python, Colab, visualization, interpreting metrics, and explaining technical limitations. I want to strengthen my skills in deployment, reproducible experiments, security evaluation, and testing on physical edge or telecom hardware. These are important next steps toward using AI responsibly in operational networks.
